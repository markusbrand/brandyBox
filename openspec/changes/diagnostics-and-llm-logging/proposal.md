## Why

When background sync errors, timeouts, or data discrepancies occur across BrandyBox clients (macOS, Windows, Linux), diagnosing the root cause is difficult and time-consuming. Today, desktop clients only record errors locally in unstructured text files and send a bare `last_sync_ok: false` ping to the backend, completely dropping the error classification, affected file paths, and HTTP context. Furthermore, backend logs and client operations have no shared correlation identifier, and there is no unified mechanism to inspect cross-client health or feed rich diagnostic context into an LLM for automated troubleshooting.

Establishing a centralized, structured diagnostic event stream, a Raspberry Pi CLI inspector (`brandybox-doctor`), and an Admin Web UI with one-click LLM prompt exports makes every client and server failure completely transparent and instantly diagnosable by an AI agent or developer.

## What Changes

- **Correlated Structured Telemetry**: Introduce an `X-Sync-ID` / `X-Trace-ID` correlation identifier generated by clients per sync run and propagated across client operations and server request logs.
- **Client Error & Summary Reporting**: Update `client-tauri` to capture structured sync summaries (duration, files processed, failures) and structured error events (error codes, HTTP status, file paths, phase), pushing them to the backend via a buffered `/api/telemetry/events` endpoint with offline resilience. High-volume debug logs remain local only.
- **Backend Diagnostic Ingestion & Persistence**: Extend the backend telemetry service to persist sync summaries and diagnostic events in SQLite with indexing on trace ID, device, user, and timestamps, alongside rolling JSONL logs.
- **Raspberry Pi CLI Diagnostic Tool (`brandybox-doctor`)**: Provide a CLI command runnable directly on the Pi (via `ssh pi` or `docker exec`) supporting `--summary` (system & client sync health overview), `--trace <id>` (correlated client/server event timeline), and `--llm-prompt` (formatted markdown bundle optimized for LLM root-cause analysis).
- **Web UI Diagnostics Dashboard**: Upgrade the Web Settings/Admin diagnostics drawer into a full Diagnostics view with a Client Sync Matrix, filterable error event feed, and a one-click `[Copy LLM Context]` action for rapid triage.

## Capabilities

### New Capabilities
- `central-telemetry`: Structured diagnostic event ingestion, sync cycle summaries, offline event buffering, and `X-Sync-ID` correlation between clients and backend.
- `pi-diagnostics-cli`: Raspberry Pi CLI inspection tool (`brandybox-doctor`) providing system health summaries, correlated trace timelines, and LLM-ready markdown diagnostic exports.
- `diagnostics-dashboard`: Web UI Admin Diagnostics view featuring a multi-client sync matrix, structured error drill-down, and one-click LLM context export.

## Impact

- **Backend API & DB**:
  - `backend/app/telemetry/`: New models/schemas for `sync_summaries` and `diagnostic_events`, ingestion endpoint `POST /api/telemetry/events`, admin query endpoints.
  - `backend/app/middleware.py`: Trace ID request header middleware.
  - New CLI module `backend/app/cli/doctor.py` (exposed as `brandybox-doctor`).
- **Client Desktop (`client-tauri`)**:
  - `client-tauri/src-tauri/src/sync.rs`: Structured error classification, sync summary compilation, and `X-Sync-ID` header injection.
  - `client-tauri/src-tauri/src/api.rs`: Telemetry batch submission API.
  - Offline event spooler/queue in local client state.
- **Web Frontend (`web`)**:
  - `web/src/pages/SettingsPage.tsx` (or new `web/src/pages/DiagnosticsPage.tsx`): Sync matrix, error event inspector, and LLM prompt clipboard copy.
  - `web/src/api/http.ts`: Client endpoints for telemetry queries.
